# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## What this is

Agent Platform (`ap`) — a minimal coding-agent CLI optimized for raw speed. Bun + TypeScript, **zero runtime dependencies** (Bun built-ins only: fetch, Bun.serve, Bun.spawn, node:readline). Speaks the OpenAI-compatible chat-completions wire format to any provider (OpenCode Go, OpenRouter, NVIDIA NIM, arbitrary base_url). Ecosystem surfaces: MCP client (`mcp.ts`), ACP agent for Zed (`acp.ts`), skills.sh-format skills, lifecycle hooks/webhooks. npm package: `@sanjaydoppalapudi/agentplatform`, bin name `ap`.

## Commands

```sh
bun run dev              # run from source (bun run src/index.ts)
bun x tsc --noEmit       # typecheck — run after every change (prefer a local typescript install; bunx can miss lib.d.ts)
bun test tests           # unit tests (pure/local) — release-gated in CI
bun run smoke            # real user-path smoke (scripts/smoke-userpath.ts) — no LLM for most checks
bun run compile          # build ap.exe + prewarm run (Defender scans happen at build time, not first launch)
bun run dist             # cross-compile all four platform binaries into dist/
bun run src/index.ts tool grep '{"pattern":"foo"}'   # exercise one tool directly, no LLM call
bun run src/index.ts run -p "task" --cwd <dir>       # one-shot agent run (needs a provider key)
bun run src/index.ts mcp list --cwd <dir>            # connect configured MCP servers, list tools (exit 1 if any down)
bun run src/index.ts pr --title "x"                  # PR preview (exit 2 without --yes)
bun run src/index.ts tmux list                       # unix tmux, or clear Windows fallback
echo '{"jsonrpc":"2.0","id":1,"method":"initialize","params":{"protocolVersion":1}}' | bun run src/index.ts acp   # ACP handshake smoke test
```

Releases: `git tag v0.x.y && git push --tags` → `.github/workflows/release.yml` cross-compiles and attaches `dist/*` to the GitHub release, which `install.ps1` / `install.sh` download.

On Windows, `bun build --compile` cannot overwrite a **running** ap.exe (EPERM) — rename it aside first (`Rename-Item ap.exe ap.exe.old-<stamp>`), then build.

**Smart App Control / Device Guard can block locally built binaries.** If `VerifiedAndReputablePolicyState` is 1 (`HKLM:\SYSTEM\CurrentControlSet\Control\CI\Policy`), a freshly compiled unsigned `ap.exe` may not launch ("blocked by your organization's Device Guard policy") even though the build succeeded — and if the repo dir is on PATH, rebuilding **breaks the user's `ap` command**. The verdict is per-file cloud reputation, so it changes over time: builds were blocked here in early Aug 2026, then the same unsigned output (and even the previously blocked binary) launched fine weeks later once reputation caught up. **Always prove it empirically after compiling** (`ap.exe --version`; the `compile` script's prewarm run does this). If blocked: verify changes by running from source (`bun src/index.ts …`) and rename the exe aside (e.g. `ap.exe.blocked-by-sac`) so the committed shims keep `ap` working — `ap.cmd` for cmd/PowerShell, extensionless `ap` (sh) for macOS/Linux/WSL/Git Bash; both pinned in `.gitattributes` because their line endings are load-bearing. PATHEXT prefers `.EXE`, so the shims only take effect when no runnable `ap.exe` is present.

## Architecture

One process, one event stream. `agent.ts` runs the loop and emits `AgentEvent`s (`text`/`reasoning`/`tool_start`/`tool_end`/`turn_end`/`done`/`error`); every front-end — REPL (`repl.ts`), one-shot/NDJSON (`run.ts`), HTTP+SSE server (`server.ts`) — is just a different renderer of that same stream. To add a capability, emit an event; never print from inside the loop or tools.

Data flow per turn: `repl/run/server` → `runTurn()` (agent.ts) → `streamChat()` (provider.ts, plain fetch + retry/backoff) → `consumeSSE()` (stream.ts, assembles text + index-keyed tool_call deltas, strips `<think>`/`reasoning_content` into the reasoning channel) → tool dispatch (tools/index.ts registry) → results appended as `role:"tool"` messages → repeat until no tool calls.

- **Modes** (`config.mode`): `code` sends the full tool-schema set for the profile; `plan` sends only the read-only subset so mutation is structurally impossible, plus a backstop block in agent.ts for hallucinated calls.
- **Web access** (full profile only): `websearch` scrapes DuckDuckGo's HTML endpoint with plain fetch (no API key); `fetch` is plain HTTP(S) text only. `render:true` is intentionally disabled until a renderer can enforce hostname policy throughout DNS, socket connection, and redirect handling — never bundle or download a browser as a workaround.
- **Sessions** (`session.ts`): append-only JSONL per session under `<dataDir>/sessions/`, no database. A torn final line is skipped on load — this is the crash-safety mechanism; never buffer writes.
- **Server** (`server.ts`): endpoint shapes deliberately mirror what 5Pages' `build-server/lib/opencode-runtime.js` calls on opencode (session create → blocking message → SSE events) so it can replace opencode there with a thin adapter.
- **Credentials** (`creds.ts`): keys live in `<dataDir>/credentials.json`, ACL-locked to the current user. On Windows, icacls grants must use fully-qualified `DOMAIN\user` — a bare username silently grants to nobody when the machine name matches the username.
- **Per-tool permissions** (`permissionFor` in tools/index.ts, enforced in agent.ts runOne): config `permission` — `{"edit": "ask", "fetch": "deny", "mcp_*": "ask", "bash": {"git push*": "ask", "*": "allow"}}`. Rules win over the coarse `permissions` mode; `allow` skips only the ask gate (sandbox/bashGuard still apply); `ap tool` (developer CLI) bypasses by design. Active in all profiles — enforcement config is not a --light "feature". **Compound bash** (`&&`/`||`/`|`/`;`/`&`) is split with `splitShellSegments` and the **strictest** segment verdict wins (an `allow *` cannot sneak a denied `git push` past via chaining).
- **Sandbox is read-scoped too** (`tools/shared.ts`): `readRoots` = workspace + dataDir skills/memory/commands + session plans + `~/.claude/skills`; reads elsewhere permit-gated (read/grep/glob AND bash via `scanCmdPaths` path-token scan incl. `..` escapes). `isPrivatePath` (dataDir sessions/checkpoints/credentials.json/config.json + `~/.ap/trusted-workspaces.json`) is hard-denied for read AND write — permits cannot override. Loop mode exits 3 on a `LOOP_BLOCKED:` reply instead of letting the model wander when a goal doesn't apply.
- **Sandbox modes** (`config.sandbox` = `workspace`|`container`|`off`, `--sandbox`): `workspace` (default) is the in-process guardrail above — file containment holds, but `bash` is host code execution, so a runtime-derived path (base64/octal decode, socket from a script) can escape the pattern scan (proven). `container` runs each `bash` inside docker/podman (`containerArgv` in bash.ts): `run --rm -i --network none -v cwd:/workspace -w /workspace --security-opt no-new-privileges <sandboxImage|alpine> /bin/sh -c` — only the workspace is mounted, dataDir/credentials are unreachable, egress off unless `network:"allow"`. `containerRuntime()` caches docker>podman; a clear ToolError when neither is present. `background:true` is refused in container mode. File tools stay in-process (already contained). **These are privileged config keys** (trust-gated; not in `SAFE_PROJECT_CONFIG_KEYS`).
- **Network egress policy** (`config.network` = `"allow"`|`"deny"`|`string[]`): `egressPolicyBlock` (fetch.ts) is the one gate for `fetch`, `websearch`, and bash URL tokens (`scanEgressPolicy`). Metadata/link-local hosts are blocked under **every** policy (fixed floor); beyond that, `deny` blocks all and a `string[]` is a suffix-match allowlist. Best-effort in-process (a scanner can't see a socket from a script); OS-enforced only by `--network none` in container mode.
- **models.dev** (`models.ts`): provider/model catalog, fetched lazily and disk-cached 24h. Never loaded on the startup path.
- **Loop mode** (`loop.ts`): `ap loop -p goal [--check cmd]…` — work turn → objective check commands (exit-0 gates, fed back on failure) → auditor turn (fixed-byte VERIFY_PROMPT, read-only steering, `LOOP_DONE` sentinel, confirmation passes when the audit used mutating tools). Stall detector (2 identical audits + no mutations → exit 2) and auto-compaction via shared `compact.ts` keep unlimited looping affordable.
- **Real-git** (`git.ts`, distinct from checkpoint.ts's shadow repo): `/commit [--staged|--sign]` drafts a message for `y/N` approval; **never pushes**; refuses protected branches unless the user accepts an `ap/<slug>` switch. `git.autoBranch` (config) creates that branch automatically on the first mutating tool call (`maybeAutoBranch` in agent.ts, latched per cwd). `/pr` + `ap pr` wrap `gh pr create` (CLI gated by `--yes` / `AP_PR_YES`). Pure helpers are unit-tested. Gotcha: the git wrapper trims combined output, which strips porcelain's leading space on line 1 — always parse status with `parsePorcelain`, never a fixed-width slice.
- **Compaction 2.0** (`compact.ts`): shared path for REPL + loop — archives under `<dataDir>/archives/`, `parentSessionId`, `preCompact`/`postCompact` hooks, `/archives` + `/restore-context`, optional auto-memory cards (`autoMemory`).
- **Repo-keyed memory** (`memory.ts`): `git rev-parse --git-common-dir` → `memory/git-<hash>/`; legacy flat `memory/` still read as fallback. Snapshotted into the system prompt once per session.
- **Steer** (`steer.ts`): queue coaching for the next user message (REPL `/steer`, ctrl+s mid-turn) — never inject mid-history.
- **REPL `!` shell escape** (`repl.ts`): a prompt-bar line starting with `!` runs the rest in the user's own shell (`shellPrefix`, inherited stdio, cwd = workspace) instead of sending it to the model — like `!` in psql/gdb. It is the USER's terminal, so it deliberately bypasses the agent guardrails and `agentChildEnv` marker (not a model tool; available in all profiles). `/` and `:` remain command prefixes; `!` is the third.
- **Channels** (`channels.ts`): in-process note bus for `agent {channel}` and flow `channel.post/read`; drained into the next turn like task notes.
- **tmux** (`tmux.ts`): optional unix adapter (`ap tmux` / `/tmux` / `/spawn`); `Bun.which("tmux")` — clear fallback message on native Windows.
- **repomap** (`tools/repomap.ts`): full-profile outline via ripgrep defs. **Windows gotcha:** spawn the absolute path from `Bun.which("rg")` (`requireRg` in shared.ts) — bare `"rg"` ENOENTs when which finds a user-local install; never set spawn `cwd` to a *file* path (grep file targets use `dirname` + absolute search path).
- **Background processes** (`bg.ts`): `bash background:true` appends to `<dataDir>/background.jsonl` (pid/cmd/cwd/log, torn-line tolerant like sessions); `/ps` + `ap ps [tail|kill]` list/tail/kill, pruning dead entries past the 7-day log retention. **Windows gotcha (fixed, keep it):** a raw fd passed via `stdio` is silently dropped for detached children — verified with BOTH node:child_process and Bun.spawn — so the background command redirects inside the shell itself (`{ cmd ; } > "log" 2>&1`, PowerShell `*>`, cmd `( ) > log 2>&1`). Never go back to fd inheritance.
- **Background task delegation** (`tasks.ts`, `tools/subagent.ts`): `agent {background:true}` detaches the subagent from the turn — the tool returns immediately, the child (its OWN `AbortController`, never the turn signal) runs on, and its result is queued as a note that `drainTaskNotes()` folds into the NEXT user message (the loop.ts pending pattern — never injected mid-turn, history stays append-only). `runSubagent` (extracted from the agent tool so the sync tool, background tasks, and workflows share one child runner) spawns `ap run --json --light`. `/tasks [kill <id>]` lists/stops; `<dataDir>/tasks.jsonl` is the append-only audit trail; run.ts `settleTasks()` before `process.exit` (children die with the parent on Windows). Full profile only.
- **Dynamic workflows** (`flow.ts`): `ap flow <name> [args…]` / `/flow` — a workflow is a USER-written `.ap/workflows/<name>.ts` (or `<dataDir>/workflows`) that `export default async function ({ agent, parallel, log, args, channel })`. Determinism lives in the script; intelligence in bounded `agent()` calls (each = one `--light` child via `runSubagent`; `schema` forces JSON with a single feed-back-the-error retry via `extractJson`). `boundedParallel` caps concurrency at `min(8, cores−2)`; `MAX_FLOW_AGENTS=50` backstops runaways. **No `flow` tool exists — a model can never launch one** (depth-1, like subagents running `--light`); same trust tier as `hooks.onDone` (local code the user placed). Progress → stderr (REPL: dim), result → stdout, so `ap flow x | jq` works. `resolveFlowPath` treats names as identifiers (`^[\w-]+$`) so a name can't traverse; an explicit `.ts` path is allowed (the user typing it). Full profile only.
- **Artifacts** (`tools/artifact.ts`): `artifact {title, html}` writes a self-contained page to `<dataDir>/artifacts/<stamp>-<slug>.html`. The slug is the only model-controlled path segment — alphabet-validated (`^[a-z0-9][a-z0-9-]*$`) AND containment-asserted (the skills-installer traversal is why). A no-network CSP meta (`default-src 'none'`) is injected so model HTML can't exfiltrate; 2MB cap. `/artifacts` lists; `ap serve` exposes `GET /artifacts/<file>.html` (same regex + containment on the route). HTML only (`md.ts` renders ANSI, not HTML). Full profile only.
- **Named agents** (`agents.ts`): opencode/Claude-Code-style profiles — `.ap/agents/<name>.md` > `.claude/agents` > `<dataDir>/agents`, frontmatter `description`/`model`/`tools` + body as role instructions. Applied in run.ts (`--agent`): body appended to the system prompt, model override (provider/model split only when the prefix is a configured provider), `tools:` → `config.toolFilter` (programmatic schema whitelist in toolSchemasFor — constant per process, cache-safe). The agent tool's `{name}` arg routes subagents through the same path; one line per profile in the system prompt (snapshotted). Full profile only.
- **BOM + line endings are load-bearing** (learned the hard way): a UTF-8 BOM voids `---` frontmatter (agents/skills) — strip it at every `readFileSync`; `.env` redaction split on `\n` only, so CRLF files leaked every secret (`.` excludes `\r`, `$` without `/m` is end-of-input); `edit` must re-prepend a BOM it detected at BYTE level (`file.text()` eats it). Never pass a model-authored replacement as the string argument of `String.replace` — `$$`/`$&`/`` $` ``/`$'` are substitution patterns; use a function replacer.
- **Skills** (`skills.ts`): skills.sh/Claude-format SKILL.md packs (nested folders discovered). Discovery order `.ap/skills` > `.claude/skills` > `<dataDir>/skills` > `~/.claude/skills`; one line per skill in the system prompt (snapshotted per session), body read on demand. `/skills reload` rebuilds the catalog. Installer uses the GitHub tree API + raw.githubusercontent — never git/npx. Full profile only.
- **ACP adapter** (`acp.ts`): `ap acp` — Agent Client Protocol v1 (Zed et al.) over stdio, newline-delimited JSON-RPC; stdout is protocol-only (logs → stderr). Just another AgentEvent renderer: text/reasoning → message/thought chunks, tool_start/end → tool_call(_update), sandbox permits → `session/request_permission` (native editor dialogs), plan/code → ACP session modes, `session/cancel` → AbortController, `session/load` replays persisted history. Editor-configured MCP servers pass through to `initMcp`. Handlers are dispatched un-awaited so cancel is processed mid-turn. Slash commands are advertised via `available_commands_update` (Zed blocks unadvertised ones client-side) and arrive as `/name args` prompt text, handled locally in `session/prompt` with no model call. Gotcha: `session/set_mode` must return `{}` — Zed's client rejects `null` and reverts the mode picker.
- **Lifecycle hooks** (`agent.ts` fireLifecycle): config `hooks.onDone`/`hooks.onError` — shell command (AP_EVENT/AP_PAYLOAD env) or http(s) URL (JSON POST). Fire-and-forget with a pending-set; run/loop `await lifecycleSettled()` before process.exit because Windows kills children of an exiting parent. Cron was deliberately CUT — OS schedulers invoking `ap run` are the supported pattern; never build a scheduler daemon.
- **MCP client** (`mcp.ts`): zero-dep JSON-RPC 2.0 over stdio (Bun.spawn, newline-delimited; Windows `.cmd` shims run under `cmd /c`) or Streamable HTTP (fetch, `mcp-session-id` tracked). Config = Claude Code's format: project `.mcp.json` (walked upward, wins) merged with `mcpServers` in ap.config.json/`<dataDir>/config.json`. Front-ends `await initMcp()` before the FIRST turn (REPL kicks it off in the background at startup) — never on the startup path. Tools register once per process as dynamic tools (`registerDynamicTools` in tools/index.ts) named `mcp_<server>_<tool>`, sorted, then frozen → schema bytes stay stable for caching. Soft auto-background (~30s, `mcpAutoBackgroundMs`) queues long calls as tasks; `/mcp reload` + `clearDynamicTools` rebuild mid-session (prefix-cache miss accepted). `readOnlyHint === true` ⇒ readOnly (plan-mode visible, parallel-safe); everything else is treated as mutating, and the plan-mode backstop in agent.ts blocks it. Dead servers warn + skip. Full profile only; subagents run `--light` so they never spawn servers.

**The `--light` profile is frozen**: core six tools, smallest prompt, no memory/skills/plans/subagents/checkpoints — new features must never leak into it (gate on `config.light`).

## Invariants that make it fast — do not break

- **Byte-stable prompt prefix.** The system prompt (`prompt.ts`) contains no timestamps or dynamic ordering, tool schemas are in a FIXED registry order (`tools/index.ts`), and messages are append-only. This is what makes provider-side automatic prefix caching hit (~85–90% of prompt tokens). Anything that varies per request must go after the history, never into the system prompt or tool list.
- **Zero npm runtime deps and lazy per-mode `import()`** in `index.ts` — startup is ~45ms compiled; adding a dependency or a top-level import of a mode is a regression.
- **Every tool output is capped** (read 50KB / bash 30KB middle-out / grep 200 matches / glob 300 files / 40KB backstop in `execTool`). New tools must self-cap.
- **grep AND glob shell out to ripgrep** so `HARD_IGNORES` dirs (node_modules, builds, trash, dist*, …) are pruned during traversal — the target repo (5Pages) has ~5,000 generated files that make post-filtering unusable.
- **Reasoning is never re-sent**: `<think>` blocks and `reasoning_content` are surfaced to the UI but excluded from stored history.
- Terminal rendering is line-buffered markdown (`md.ts`) and a raw-mode line reader (`input.ts`); the readLine `prompt` string must be single-line — it is re-rendered on every keypress.
- **Input rendering is wrap-aware and frame-owning** (`input.ts`): readLine tracks `drawnAbove` (frame top row + rows the input wrapped onto) and rewinds by it before every `\x1b[J` — without that, a wrapped input strands its first row and the whole block marches down one row per keystroke (the "shredded box"). `cursorGeometry()` in theme.ts does the deferred-wrap math (`(len-1)/cols`, never `len/cols`); never emit `\x1b[0A`/`\x1b[0C` (CSI 0 means 1). readLine redraws the frame top itself every render, so the box survives resizes and ctrl+o replays, and the status row (= bottom edge) is drawn under menus too. `tests/vt.test.ts` has a minimal virtual terminal that replays these scenarios — extend it rather than eyeballing a terminal.
- **ANSI nesting rule**: never wrap a colored span around content that may contain its own SGR reset — the inner `\x1b[0m` kills the outer style (this broke the frame's bottom edge and bold-with-code in md.ts). Paint the pieces around the content (frameBottom) or close with attribute-specific codes: SGR 22 (intensity), 23 (italic), 39 (foreground).
- **Themes + input frame** (`theme.ts`): a theme is a palette of ANSI codes; repl.ts's dim/cyan/green/… helpers resolve `currentTheme()` per call, so `/theme` switches apply instantly without touching ~80 call sites, and ui.ts's diff colors are getters for the same reason. The prompt frame is top edge (mode label) + a left edge on the input line + the status row as the bottom edge — only the input line carries a left edge, so wrapped text can never break the box. `frameTop`/`frameBottom` do width math on VISIBLE length (ANSI-stripped) and truncate rather than wrap. NO_COLOR/TERM=dumb force mono.

## Legacy-name compatibility (post-rebrand)

The tool was renamed harness → Agent Platform. Keep accepting the old names: data dir `~/.harness` (new: `~/.ap`), project config `harness.config.json` (new: `ap.config.json`), project notes `HARNESS.md` (new: `AP.md`) — 5Pages still uses `HARNESS.md`. Env vars are still `HARNESS_PROVIDER`/`HARNESS_MODEL`/`HARNESS_BASE_URL`/`HARNESS_API_KEY`.

## Alias tolerance

Weaker models misname tool arguments. `edit` accepts `old`/`old_string`/`oldText` and `new`/`new_string`/`newText` (`tools/edit.ts`), and `ui.ts` renderDiff mirrors the aliases. Extend this pattern rather than letting a turn fail on argument naming.
